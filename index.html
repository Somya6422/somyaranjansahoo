Interactive 3D · Solo project · Live

VANTAGE: ZERO

A voice-controlled 3D combat flight game that runs in the browser.

Fly a Su-57 or F-35 over terrain built from real Caucasus elevation data, and command it by voice, keyboard or mouse.

  • TypeScript
  • Three.js
  • Vite
  • Web Audio API
  • Web Speech API
  • Vitest
Read the case study
Problem
Make a full flight-combat game that opens straight away in a browser (no installer, no asset packs, no API keys) and can be played entirely by voice.
What I built
A 6-degrees-of-freedom flight model running at 120 Hz, four missions plus a wave-survival mode across three theatres, a glass-cockpit HUD with a tactical map, an AI wingman and enemy drones, a voice-command layer, and assists such as autopilot and autoland.
Architecture
TypeScript compiled by Vite into a static bundle; Three.js (WebGL2) is the only runtime dependency. Audio is synthesised with the Web Audio API. Every push to GitHub deploys to Vercel.
Hardest problem
Keeping it self-contained. Terrain, aircraft, audio and dialogue are all generated locally, so the game never needs the network. A suite of 70 automated Vitest tests covers flight, missions, voice bindings and settings.
Outcome
It's live and you can play it. I made it for the Wispr Flow challenge at Hacker House Goa 2026, directing an AI coding assistant by voice dictation.

Finalist · India Innovates 2026

GIS & data · Team ASTRA-X · My part: back-end ingestion

GOD VIEW

An open-source-intelligence digital twin: live flights and satellites on a 3D globe, linked in a knowledge graph.

  • Python
  • FastAPI
  • Neo4j
  • Next.js
  • CesiumJS
  • Sarvam AI
Read the case study
Problem
Intelligence data is scattered across separate feeds, and most dashboards show isolated points instead of how events relate to each other.
Team build
A FastAPI back-end, a Neo4j graph of entities and relationships, Sarvam AI for summaries in English, Hindi, Tamil and Telugu, and a Next.js + CesiumJS 3D globe.
My contribution
The ingestion services that pull live aircraft positions from OpenSky, satellite orbital data (TLE) from CelesTrak and earthquake data from USGS, and serve them to the globe.
Hardest problem
OpenSky rate-limits requests (HTTP 429), and CelesTrak sometimes sends back an HTML error page instead of data. I added a 15-second cache, fallback data and response checks, so the globe keeps working in the middle of a live demo.
Outcome
Presented at the national finals of India Innovates 2026 at Bharat Mandapam, New Delhi, representing Odisha and my college.

Award winner · Best Innovation Team

Assistive tech · Team ASTRA-X

UNSPOKEN

A chest-mounted wearable that helps visually impaired users sense obstacles and lets non-verbal users speak through gestures.

  • Raspberry Pi Zero 2 W
  • Python
  • Node.js
  • React
  • TensorFlow Lite
  • OpenCV
  • Gemini API
Read the case study
Problem
One affordable device for two groups: people who cannot see obstacles around them, and people who cannot speak.
Team build
Two ultrasonic sensors with vibration motors for left/right obstacle alerts, an MPU6050 IMU that turns lean gestures into spoken phrases ("Yes", "No", "Help", "SOS"), and a camera for scene description. A Python sensor-fusion loop on a Raspberry Pi Zero 2 W runs all of it, and a Node.js WebSocket server feeds a live React dashboard.
Hardest problem
A Pi Zero 2 W cannot run full TensorFlow or MediaPipe. The team used TensorFlow Lite models on the device and split the work: safety features run offline, while richer scene description uses the Gemini API when a connection exists.
Outcome
Won the Best Innovation Team award, with a ₹10,000 prize, at the 36-hour CHAKRAVYUH 1.0 National Hackathon, GITA Bhubaneswar, 30–31 January 2026.

GIS & computer vision · Solo project

Smart Toll Plaza Management & GIS Command Center

An NHAI-style toll operations prototype: live number-plate recognition, a Pan-India plaza map and role-based reporting.

  • Python
  • Streamlit
  • FastALPR
  • OpenCV
  • WebRTC
  • Plotly
  • pandas
Read the case study
Architecture
A Streamlit multipage app with four pages: sign-in, Live Camera, GIS Command Center and Analytics. A CloudSQLAdapter class stores transactions, security audits and shift closures in a JSON file, behind an interface meant to be swapped for a cloud SQL database later.
Data flow
WebRTC camera frame → every third frame → FastALPR (YOLOv9 plate detector + MobileViT OCR) → confidence ≥ 0.50 → Indian plate-format check → blacklist screening or diplomatic exemption → simulated FASTag or cash charge → ledger and audit entry.
Map & analytics
A national toll-plaza registry (2,000+ rows) cleaned with pandas and plotted with Plotly's map view; analytics show payment mix and revenue by vehicle type; prices rise 1.15× in peak hours.
Hardest problem
Making a demo that runs on any machine. The data adapter needs no cloud credentials, and plate validation accepts standard, Bharat-series and diplomatic plates while throwing out OCR noise.
Scope
It's a simulation for learning and demos, and it isn't connected to live FASTag, VAHAN or NHAI systems. It grew out of my Class XII toll-management project.

Web & workflow · Team ASTRA-X

ANUMATI

A regulatory-clearance engine that models business licences as a dependency graph.

  • Next.js
  • TypeScript
  • React Flow
  • Fastify
  • PostgreSQL
Read the case study
Problem
Setting up an industrial unit in Maharashtra can take 25 to 35 or more clearances from over 15 departments. Applicants can't tell which ones can be filed together, so they file them one at a time.
Approach
Clearances are modelled as a directed acyclic graph. The engine computes the critical path, finds approvals that can run in parallel, and shows officers where files get stuck.
Team build
A Next.js + TypeScript web app (React Flow graphs, TanStack Query and Table, Zod), a Fastify + PostgreSQL server that runs the same rule engine, and a Python pipeline that drafts rules from gazette PDFs for an officer to review.
Outcome
Selected in the Smart India Hackathon 2026 college internal round (problem statement SIH26130); our idea presentation was submitted for the next round.

Desktop app · Solo project

Student Attendance Management System

A multi-role desktop app where students check in by scanning a QR code on their phone.

  • Python
  • Tkinter
  • SQLite
  • http.server
  • qrcode
Read the case study
What it does
Separate portals for teachers, students and principals; manual or QR attendance; pie-chart analytics; warnings for anyone below 75%; and a message channel for leave and correction requests.
Architecture
Tkinter interface over SQLite, with SHA-256-hashed credentials. A small HTTP server runs on a background thread and serves the phone check-in page over the local network.
Hardest problem
Stopping proxy attendance. Each QR code carries a random session token that stops working the moment the teacher closes the attendance window.
Outcome
Packaged as a downloadable Windows release on GitHub.

Becoming a data analyst is my main goal, so this is where I practise it in the open: a real analysis, my own numbers, and a live database you can query.

India's toll network, in data

My toll project came with a registry of 2,003 plazas. I treated it as a dataset and asked: where are India's tolls, who runs them, and can the data be trusted?

Plazas after cleaning
1,997
States and UTs
26
In just 4 states
53.6%

What I had to clean

  • 16 spellings of 7 funding types (Conc, Conc., CONC, Concessio…)
  • 2 longitudes that lost their decimal point (731669180 → 73.1669180)
  • 8 plazas placed 650–1,770 km outside their own state, such as Uttar Pradesh plazas with Chennai's coordinates
  • 25 plazas sharing an exact coordinate with a different plaza, a copy-paste sign
  • 6 duplicate records under different codes, and 1 cut-off state name

How I did it, and the limits

  • Profiled and cleaned with pandas, logging every change
  • Caught bad coordinates by distance from each state's median, with no map files needed
  • Answered the questions in SQL with CTEs and window functions, written for MySQL 8 and run on SQLite
  • Limits: a May 2026 snapshot with no traffic or revenue, so it shows where plazas are, not how busy they are

Discipline first, then code.

I grew up in uniform. I spent seven years, from Class VI to XII, at Sainik School Bhubaneswar: early mornings, inspections and NCC training, first in the Navy wing (NCC 'A', Grade A) and then the Army wing (NCC 'B'). That's where I learned to prepare properly, own my part of a team and finish what I start.

Now I study Computer Science & Engineering at GITA Autonomous College and spend most weekends building with my hackathon team, ASTRA-X.

We started ASTRA-X at the beginning of 2026, and it's three of us: Swagat Swarup Sahu, Shubham Mohapatra and me. Since then we've won Best Innovation Team at CHAKRAVYUH 1.0, made the national finals of India Innovates 2026 and cleared the Smart India Hackathon 2026 college round. We're still going.

Computers have been part of my life since Class VI, when Computer Science became my additional subject and I picked up the basics of HTML, CSS and JavaScript. Python and MySQL came in Class XI and XII, and I'm still polishing both. I love building, changing and rebuilding things on that big screen, so for me this is a passion, not just a way to earn.

My main goal is to become a data analyst, which is why I completed the Google Data Analysis with Python specialization. Along the way I want to be a good all-round software engineer. I've learned the backend through hackathons and projects, because once you understand the backend of anything, the next path gets easier: you can make yourself understood, understand others and improve with their suggestions.

How I build software

  • Make it work end to end. In the toll system that means camera frame to ledger entry; in VANTAGE: ZERO, spoken command to moving aircraft.
  • Plan for things breaking. GOD VIEW falls back to cached data when a feed rate-limits; the toll system runs without a cloud database.
  • Be exact about my part. On team projects I say what I built (on GOD VIEW, that was the back-end data ingestion) and credit the team for the rest.
